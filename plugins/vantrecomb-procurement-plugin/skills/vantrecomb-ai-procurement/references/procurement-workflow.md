## Cloud connection and limits

The source implements stateless Streamable HTTP at `/mcp`, precise resource metadata at `/.well-known/oauth-protected-resource/mcp` and optional public-client registration at `/oauth/register`. OAuth binds the configured API-origin `/mcp` resource, PKCE S256 and exact callbacks. After deployment and explicit “Keep connected” consent, access remains 15 minutes and successful refresh rotates to a new 30-day idle deadline, with no fixed active lifetime. Old clients/grants default to no refresh until fresh consent; host-cached old metadata can require connection removal/recreation. The host alone manages secure storage and serialized refresh. Never record, extract or exchange tokens in AI workflows, add parallel refresh attempts, or embed credentials in this package. Revocation invalidates the authorization; normal database-backed restart preserves refresh state, while forced termination or a lost rotation response may require reconnecting.

### Same-authorization, same-context handoff

1. Verify that the live connection exposes this matching schema and the host can create a **fresh isolated browser context**, open pages, click and read DOM. A normal-context tab is insufficient because the original UI uses shared browser state. Keep the buyer's normal saved login in the original context; never ask them to log out or clear cookies/storage. Begin/complete reject existing normal access/refresh cookies. If the host lacks isolation or browser/DOM capability, report the missing capability.
2. Call `open_procurement_browser` with `action=prepare`, optionally `locale` and one supported `target` (default home; locale defaults en). No `flow_id`/`challenge` belongs in prepare. The response includes fixed `browser_url`, private `flow_id`, `account_email`, `target_path`, `requires_fresh_context=true`, and `expires_in=120`. The server saves the selected target in the binding; never construct an arbitrary URL/redirect/path or put the private flow ID in the URL.
3. In the fresh context's original tab, open exactly `browser_url`, click Begin and read the fresh `#challenge` DOM. The challenge lasts 90 seconds and is tied to that browser's HttpOnly binding cookie. Never accept a pasted challenge from a person, chat, another page or browser. Keep flow/challenge private and transient, with no chat/log/file disclosure.
4. Call `action=bind` with exactly `flow_id` and `challenge` through the same MCP authorization/access reference as prepare. Do not add target/locale to bind or switch accounts. Click Continue in the same original browser tab. Browser complete consumes the binding once and navigates to the saved original website target; do not call complete by raw HTTP or copy cookies/CSRF values into AI requests. Continue ordinary website navigation in this same isolated context/tab.

### Lifetime, credentials and downloads

Prepare lasts 120 seconds, challenge 90 seconds. Delegated sessions last at most ten minutes, capped by the original access deadline, with no sliding renewal. Plugin refresh is handled by the host and never renews website TTL. Restart or inconsistent instance state safely invalidates the ephemeral session; revoked/expired reference or changed scope/consent/client/account is checked on each delegated request. A new handoff may be needed.

The page manages its public per-tab `tab_id` selector in sessionStorage and CSRF in memory; `tab_id` alone cannot authenticate. Authentication still needs the separate HttpOnly/Secure/Strict cookie and live OAuth reference/grant. No OAuth access/refresh credential or password is put into URLs, page JS or localStorage. Never inspect/copy credential cookies or tokens, imitate the delegated headers, or manually install the selector/CSRF. Normal credentials are neither read nor sent by delegated transport. Failed/expired delegation, changed tab/session or accidentally mixed normal cookies must fail closed, without ordinary-login fallback or silently switching account. End delegation through the website's delegated logout; normal saved credentials and plugin grant remain unchanged.

Original file-download buttons can operate only with `me:files:download` and native ownership/single-use/IP/count rules. Delegated download records are session-bound, memory-only and expire no later than the session; every use checks current authorization and quote ownership. Do not detach or forward them as durable anonymous links. This differs from the MCP `document_link` caller-IP-bound response above; neither flow makes the MCP tool fetch/attach/stream file bytes. No customer-upload API is added.
