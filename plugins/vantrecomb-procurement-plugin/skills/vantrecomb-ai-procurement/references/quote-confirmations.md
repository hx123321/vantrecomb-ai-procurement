# Proposal and quote confirmation

Two ERP-requested customer stages: **Confirm proposal** uses action `accept_quote` with legacy customer_action.type `confirm_quote`; accepts current product/customization only, no order/payment/scheduling. **Confirm quote** uses `confirm_order` with legacy type `confirm_order`; accepts this version’s prices, quantities and order contact and requests one pending-review internal order on ERP sync when existing prerequisites hold. This includes order intent; do not add a third customer confirmation. Types are fixed enums, no dictionary key. Read the owned quote for current `customer_action.required`, type and version; approve/reject consume that request and disappear, while messages remain available until closed. Ordinary ERP push without an action preserves it. Payment notice preparation/preview and explicit employee sending follow order creation, independently of production approval. Draft saves, response retries and approval must not create another order or send duplicate mail. Email is not proof of payment; production still needs internal approval.

Prepare/read/execute keep the full frozen commercial payload, required name/email/phone/address, current version/revision/deadline, ownership/scopes and an explicit real user decision. Never replace these with a label-only acceptance. Unknown outcomes require reading the original durable receipt before retrying.
