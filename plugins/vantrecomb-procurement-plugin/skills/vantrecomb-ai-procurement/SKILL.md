### Connection renewal

Access lasts 15 minutes. For a connection not yet granted refresh, the buyer must reconnect and explicitly select “Keep connected” on the authorization page to enable refresh. Successful refresh rotates the credential and renews a 30-day idle window; an active connection has no fixed total lifetime and can be revoked through the buyer's API Tokens page. Server refresh state survives normal database-backed restarts. Old grants do not upgrade automatically. If the host caches old authorization metadata or cannot restart consent, the buyer may need to remove and recreate the connection.

The host handles renewal and securely stores the latest credentials. Never ask for passwords or tokens in chat. Never ask the buyer or AI to copy, extract, record or exchange access/refresh tokens, inspect credential cookies, or implement a second refresh loop. Refresh is serialized by the host; replay or loss of a rotation response can require reconnecting. On expired/revoked credentials or failed renewal, stop dependent calls and use Connect / reconnect. Reauthorize only the scopes required for the request; do not use a local client or normal browser session to bypass cloud authorization.

### Normal login to the original website

Plugin API operations still require their own API scopes; the normal website runs under its existing account permissions and object ownership. For every AI business action, still require the buyer's effective authorization and any applicable exact-payload safety confirmation. Signing in is not blanket authorization to act.

Prefer an incognito browser context; if unavailable, use the ordinary browser. The host must still control the target tab, open pages, click, read DOM and use the same-origin page flow. Report missing browser capabilities rather than treating unavailable incognito mode alone as a blocker. A verified valid same-buyer login can enter the original website directly; a repeated handoff reuses server-confirmed same-account access or refresh-only login without changing its credentials. If another account is present, the trusted handoff page displays the server-identified current and target names/emails and asks for a switch. Confirm only when the buyer explicitly authorizes that displayed switch. Cancellation, closing or going back preserves the original login and cookies. A changed browser identity, stale confirmation or expired/replayed handoff requires fresh verification. An approved switch replaces only this site's current browser session, without global logout or revoking other sessions/grants. Never silently switch, clear credentials or guess identities.

When a new website login is needed, call `action=prepare` with optional supported `locale` and `target`. The reviewed target enum is `home` (default), `profile`, `quotes`, `orders`, `shipments`, `folder`, selecting original website pages. Keep private `flow_id` and open exactly the returned fixed `browser_url` in the chosen context. Click Begin and read the fresh `#challenge` from that original tab. Call `action=bind` with exactly that flow ID and challenge over the same MCP authorization/access reference, then click Continue in the original tab for one-time completion and any trusted-page account-switch confirmation. The website creates or reuses its normal session and enters the saved original target. Never provide an arbitrary URL/path/redirect, accept a challenge from chat/another person/page/browser, or share flow/challenge/confirmation values in URLs, chat, logs or files. The server does not open the browser.

Prepare lasts 120 seconds and the browser challenge 90 seconds; these limit the handoff, not the normal website session. Website lifetime, refresh, downloads and logout are the same as manual login, with the original pages and features. Website logout/expiry does not revoke the plugin: if the plugin still has valid authorization, obtain a new one-time handoff without repeating consent. Never replay an expired/consumed ticket. Plugin revocation prevents new prepare/bind/complete operations; it does not log out an established normal website session, which follows its own normal lifecycle. To end that website login, use its normal website logout in the chosen context.

OAuth access/refresh tokens never go to the website or its URLs. The website itself handles its normal short access and refresh cookie exactly as in manual login; do not extract, copy, log or manually install either website or OAuth credentials. There is no second per-page delegated session, read-only reader or special quote-folder permission requirement. ## Local skill (Python 3.10+, standard library only)

Use this section only for a separately requested local workflow with independently verified server/client configuration. It is not a fallback for unavailable cloud tools, failed OAuth, missing scope or denied account access. The bundled client's historical routes and lifetimes do not prove current deployment support.

Use `scripts/vantrecomb_api.py` for all API calls; no pip packages, curl or ERP/browser/private management endpoints are needed. An optional `.env` beside `SKILL.md` configures API origin/client ID; process environment wins. Real `.env` and sessions must never be committed or included in a plugin archive.

```powershell
python scripts/vantrecomb_api.py guide
python scripts/vantrecomb_api.py catalog products
python scripts/vantrecomb_api.py product BC-001 --locale en
python scripts/vantrecomb_api.py scopes
python scripts/vantrecomb_api.py auth login --scope "me:quotes:read"
python scripts/vantrecomb_api.py auth device --scope "me:quotes:read" --no-browser
python scripts/vantrecomb_api.py auth status
python scripts/vantrecomb_api.py request GET /api/v1/ai/me/quotes
python scripts/vantrecomb_api.py request PATCH /api/v1/ai/me/profile --data '{"address":"..."}' --idempotency-key <unique-value> --confirm
python scripts/vantrecomb_api.py auth logout
```

Both login commands use the existing Device Authorization flow: the buyer approves in a browser; the client exchanges and privately caches a 15-minute session outside the skill directory without printing credentials. Windows sessions use user-bound DPAPI encryption; other systems restrict the short-lived file to its owner. Reauthorize after expiry or on another machine. `auth logout` clears local credentials; revoke the server grant through the buyer's API Tokens page.

Optional manually created tokens use secure environment variables `VANTRECOMB_API_TOKEN` and `VANTRECOMB_RFQ_TOKEN`; do not pass tokens in command arguments. RFQ tokens remain bound to their RFQ and expire after 30 minutes. Local POST/PATCH requires effective explicit buyer authorization, which may be carried forward under the same rule above; `--confirm` records that authorization but does not replace it. Every write requires an idempotency key.
